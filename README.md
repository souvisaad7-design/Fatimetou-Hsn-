# موقع جمعية عون وسند الخيرية

مشروع React (Vite + TypeScript) مستقل تماماً عن الموقع الرسمي للجمعية، ويضم ثلاث واجهات منفصلة:

| الرابط | الواجهة | نقطة التشغيل |
|---|---|---|
| `/` | **بوابة المنتسبين (اللجنة الانتسابية):** التسجيل، «وضعيتي» (الحالة، القائمة والمشرف، الانتساب الشهري، التبرعات)، وحملات التبرع | `index.html` ← `src/entries/home.tsx` |
| `/admin/` | **لوحة الإدارة:** لوحة المعلومات، الطلبات، المنتسبون، الانتساب الشهري، القوائم والمشرفون، الحملات والتبرعات، الإعدادات | `admin/index.html` ← `src/entries/admin.tsx` |
| `/assistant/` | **المساعد الذكي** (مستقل) | `assistant/index.html` ← `src/entries/assistant.tsx` |

## نظام اللجنة الانتسابية

- **بوابة الدخول:** قبل دخول الموقع يختار كل زائر «لدي حساب» (الهاتف وكلمة السر) أو «مستخدم جديد» (استمارة وكلمة سر). صاحب الطلب الجديد يبقى في شاشة «طلبك قيد المراجعة» ولا يدخل الموقع حتى تقبله اللجنة أو أحد المشرفين (من صفحة «الطلبات»؛ ومن يقبله مشرف يدخل قائمته مباشرة). كلمات المرور يديرها Supabase Auth.
- **المنتسب المقبول:** يحصل على رقم منتسب (AWN-0001)، ويتابع من «وضعيتي» حالة طلبه، وقائمته ومشرفه، وأشهر انتسابه (مدفوع / بانتظار التأكيد / غير مدفوع)، ويبلغ عن دفعة، ويتبرع للحملات.
- **الإدارة:** قبول أو رفض الطلبات مع تحديد القائمة، وتأكيد الدفعات والتبرعات، وتسجيل الدفعات المستلمة، ومتابعة من دفع ومن لم يدفع كل شهر حسب القائمة، وإدارة القوائم والمشرفين والحملات، وتصدير CSV، ونسخ احتياطي واسترجاع.
- **الانتساب حسب القدرة:** لا مبلغ إلزامي؛ المنتسب يختار مبلغه الشهري، والمبالغ بالأوقية القديمة.
- **«قائمتي» للمشرف:** يدخل المشرف برقم هاتفه المسجّل في قائمته، فيرى منتسبيه بالألوان (أخضر دفع، أصفر ينتظر التأكيد، أحمر لم يدفع)، ويسجّل الدفعة بضغطة واحدة بمبلغ المنتسب، مع «تراجع».
- **إثبات الدفع:** المنتسب يرفع صورة الإيصال (تُضغط تلقائياً)، فيراها المشرف أو اللجنة ويؤكّد الدفعة.
- **التذكير اللطيف:** صفحة «التذكيرات» فيها من لم يدفع هذا الشهر برسالة ودّية جاهزة (نسخ، SMS، أو كل الأرقام لنظام الرسائل الجماعية)، ومن تأخر شهرين فأكثر برسالة لمشرفه ليطمئن عليه. الإرسال الآلي يحتاج خادماً ومزوّد رسائل.
- **الالتزام لا المبلغ:** نسبة الأشهر المدفوعة من المستحقة، والمنتسب يغيّر مبلغه الشهري متى شاء من «وضعيتي».

### قاعدة البيانات (Supabase)

النظام متصل بمشروع Supabase **awn-wa-sanad-membership** (`ddgqbyktpkrgewxrnrdf`، منطقة باريس).

- **الجداول:** `members`، `lists`، `admins`، `payments`، `campaigns`، `donations` — في `supabase/migrations/20261108220000_membership_system.sql`.
- **الصلاحيات (RLS):** المنتسب يرى بياناته فقط؛ المشرف يرى قائمته وطلبات التسجيل الجديدة؛ المسؤول يرى كل شيء. لا كتابة مباشرة على الجداول، وكل تعديل عبر دوال آمنة (`approve_member`، `record_payment`، `report_payment`...) تتحقق من الدور.
- **التسجيل:** دالة الخادم `supabase/functions/register` تنشئ حساب الدخول (الهاتف + كلمة المرور) وطلب الانتساب معاً.
- **الدخول:** برقم الهاتف وكلمة المرور (6 أحرف على الأقل)، والجلسة تنتهي بإغلاق التبويب.
- **المسؤول الأول:** أول من يدخل لوحة الإدارة (`/admin/`) بحسابه ويضغط «اجعلني المسؤول الأول» يصبح مسؤولاً، ولا يظهر الزر بعدها لأحد. مسؤولون إضافيون يُضافون إلى جدول `admins` من لوحة Supabase.
- **المشرفون:** يعيّنهم المسؤول من «القوائم والمشرفون» باختيار منتسب معتمد له حساب، فيدخل لوحة «قائمتي» بحسابه.
- **المفتاح في الواجهة** (`src/features/membership/services/supabase.ts`) هو المفتاح العام (publishable)، والحماية في RLS والدوال.

| الملف | الدور |
|---|---|
| `src/features/membership/types.ts` | نماذج البيانات: منتسب، قائمة، دفعة، حملة، تبرع |
| `src/features/membership/services/api.ts` | كل العمليات (دوال Supabase) والحسابات |
| `src/features/membership/services/store.ts` | نسخة محلية من البيانات المسموح بها، تُحدَّث كل 15 ثانية |
| `src/features/membership/services/supabase.ts` | الاتصال بـ Supabase |
| `src/features/membership/portal/` | بوابة المنتسبين |
| `src/features/membership/admin/` | لوحة الإدارة |
| `src/features/membership/ui/` | مكوّنات الواجهة المشتركة |

## التشغيل محلياً

```bash
npm install
npm run dev      # خادم تطوير على http://localhost:5173
npm run build    # بناء نسخة الإنتاج في مجلد dist
npm run preview  # معاينة نسخة الإنتاج
```

## النشر

عند كل تحديث على الفرع `main` يبني GitHub Actions الموقع وينشره على GitHub Pages تلقائياً
(`.github/workflows/deploy.yml`). يجب ضبط **Settings → Pages → Source** على **GitHub Actions** مرة واحدة.

## القاعدة المعرفية للمساعد

تعليمات «مساعد عون وسند» ومعلومات الجمعية في `docs/assistant-knowledge-base.md`: يجيب بالحسانية افتراضياً، وبالفصحى أو الفرنسية حسب لغة السائل، وبإيجاز.
الردود الحالية مبنية عليه، وعند ربط نموذج ذكاء اصطناعي يُستعمل الملف كاملاً كتعليمات للنظام (System Prompt) في الخادم.

## الرد بالصوت

تحت كل رد زر «استمع»، ومن القائمة الجانبية «قراءة الردود بالصوت» لقراءة كل رد تلقائياً (`src/features/assistant/lib/speech.ts`).
يستعمل محرّك الكلام المدمج في الهاتف أو المتصفح (صوت عربي للحسانية والفصحى، وفرنسي للفرنسية)، دون خادم.
لا يوجد صوت حساني مدمج في المتصفحات؛ لصوت حساني حقيقي يلزم نموذج صوت على خادم تُستبدل به الدالة `speak()`.

## الحسانية بالحروف اللاتينية (مجموعة بيانات hassan-IA/dah)

المساعد يفهم من يكتب الحسانية بالحروف اللاتينية والأرقام (مثل `chenhou jam3iya 3oun w sanad` أو `kiv nentesb?`) ويجيبه بالحسانية.

- القاموس `src/features/assistant/data/hassaniyaLexicon.json` (4645 كلمة) مبني من مجموعة البيانات
  [hassan-IA/dah](https://huggingface.co/datasets/hassan-IA/dah) على Hugging Face (3002 جملة بالحسانية بالحرفين العربي واللاتيني).
- لإعادة بنائه: `NODE_USE_ENV_PROXY=1 node scripts/build-hassaniya-lexicon.mjs` (أو دون المتغير خارج الخادم الوسيط).
- `src/features/assistant/lib/arabizi.ts`: يكتشف الحسانية اللاتينية ويحوّل كلماتها المعروفة إلى العربية. يُحمَّل القاموس فقط عند الكتابة بالحروف اللاتينية.
- لم تُحدَّد رخصة لمجموعة البيانات على Hugging Face؛ يُستحسن أخذ إذن صاحبها قبل الاستعمال الواسع.

## المحادثة الصوتية (زر الميكروفون)

زر الميكروفون بجانب حقل الكتابة، وزر «اضغط وتكلم» في شاشة الترحيب:
يضغط الزائر ويتكلم ← يُرسل سؤاله تلقائياً عندما يسكت ← يُقرأ الرد بالصوت ← يستمع المساعد من جديد.
تنتهي المحادثة إذا سكت الزائر، أو بزر «إنهاء»، أو بمفتاح Esc. الضغط على الميكروفون أثناء القراءة يقاطعها.

- `src/features/assistant/lib/voiceInput.ts`: تحويل الكلام إلى نص بمحرّك المتصفح (Web Speech API)، دون خادم ولا مفتاح.
- `src/features/assistant/hooks/useVoiceChat.ts`: منطق المحادثة الصوتية (استماع، انتظار الرد، قراءة، ثم استماع).
- لغة التعرف في `config.ts` (`voice.arabicLang`، افتراضياً `ar-SA`، أو `VITE_VOICE_LANG`)، ويتحول إلى الفرنسية إذا تكلم بها الزائر.
- يعمل في Chrome وEdge وSafari (الحاسوب والهاتف)، ولا يعمل في Firefox (تظهر رسالة تطلب الكتابة). يحتاج https وإذن الميكروفون.

## معرض كل فيديوهات القناة (دون أي API)

زر «فيديوهات الجمعية» أو أي سؤال عن الفيديوهات يعرض داخل البوت مشغّل قائمة القناة، وتحته معرض بكل فيديوهاتها مع بحث،
والضغط على أي صورة يشغّل الفيديو داخل البوت. وأسئلة مثل «السقاية رقم 36» تعرض الفيديو المناسب مباشرة.

- القائمة محفوظة في `src/features/assistant/data/channelVideos.json`.
- تُحدَّث كل اثنين تلقائياً عبر `.github/workflows/update-videos.yml` (السكربت `scripts/update-channel-videos.mjs` يقرأ صفحة قائمة القناة العامة، دون مفتاح)، ثم يُعاد نشر الموقع.
- للتحديث يدوياً: GitHub → Actions → «Update channel videos» → Run workflow، أو محلياً `node scripts/update-channel-videos.mjs`.

## فيديوهات قناة الجمعية داخل البوت (اختياري عبر Vercel وYouTube API)

عندما يسأل المستخدم عن نشاط أو حملة أو حدث، يبحث البوت في فيديوهات قناة الجمعية على يوتيوب
(@associationaidesoutien)، ويشغّل الفيديو المناسب داخل فقاعة الرد (youtube-nocookie، دون روابط خارجية).

| الملف | الدور |
|---|---|
| `supabase/migrations/20261108090000_youtube_videos.sql` | جدول `youtube_videos`، البحث العربي/الفرنسي، RLS، ودالة `search_youtube_videos` |
| `api/youtube/sync.ts` | جلب كل فيديوهات القناة من YouTube Data API v3 وتحديث الجدول (upsert) |
| `api/youtube/search.ts` | `/api/youtube/search?q=...` يرجع أفضل 3 فيديوهات |
| `api/_lib/videoTool.ts` | أداة `search_association_videos` جاهزة لنموذج ذكاء اصطناعي مستقبلاً |
| `vercel.json` | تشغيل المزامنة يومياً (Vercel Cron) |
| `src/features/assistant/components/VideoCard.tsx` | المشغّل داخل البوت (تحميل كسول، وصور مصغّرة للفيديوهات الأخرى) |

- دوال `api/` تعمل على **Vercel** فقط. على GitHub Pages يعمل البوت بلا فيديوهات، إلا إذا ضُبط `VITE_VIDEO_SEARCH_URL` برابط مشروع Vercel.
- المتغيرات المطلوبة في `.env.example`. مفتاح يوتيوب ومفتاح service role على الخادم فقط.
- إذا فشل البحث أو لم يوجد فيديو مناسب، يجيب البوت نصياً كالعادة.

## ربط المساعد بالـ Backend لاحقاً

أنشئ ملف `.env` (أو اضبط المتغيرات في GitHub Actions):

```
VITE_ASSISTANT_PROVIDER=http
VITE_ASSISTANT_API=https://api.example.org/assistant/chat
VITE_MEMBERSHIP_URL=https://join.example.org
```

الخادم يستقبل `POST { "messages": [{ "role": "user", "content": "..." }] }` ويعيد:
- JSON: `{ "content": "...", "followups": ["..."], "actions": [{ "type": "membership" }] }`
- أو تدفق SSE بأسطر `data: {"delta":"..."}`

لا تضع مفاتيح API في الواجهة؛ مكانها الخادم فقط.

- لا يظهر زر انتساب في المساعد ما لم يُضبط `VITE_MEMBERSHIP_URL`.
- يمكن فتح المساعد بسؤال جاهز: `assistant/?q=ما شروط الانتساب`
